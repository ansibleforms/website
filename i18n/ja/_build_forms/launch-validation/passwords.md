# パスワード
{: .no_toc }

password フィールドがどのように検証、保存され、API から除外されるか
{: .fs-6 .fw-300 }

1. TOC
{:toc}

---

password フィールドは、ほかのフィールドと同じように検証されます。ただし、その値はサーバーに保持され、クライアントに返されることは
ありません。

---

## パスワードの保存場所

サーバーは、パスワードをジョブとともに、その extravars に保存します。

* これにより、 **承認** の後、ユーザーが入力したパスワードでジョブを続行できます。
* 起動時の検証が `enforce` でない場合、 **実行時のままの再起動** でパスワードを再利用できます。

保存されたパスワードは、サーバー上でだけ使われます。

---

## API が返すもの

パスワードを返す API はありません。

* REST API または MCP サーバーの `get_job` で読み取ったジョブでは、フォームのすべての `password` フィールドがマスクされます。
  list の行や YAML のサブフォームの中も同様です。
* `MASK_EXTRAVARS_REGEX` (既定は `password|secret|token` ) は、名前が一致するすべての extravar もマスクします。
  password フィールドではないシークレットのためです。

---

## 再起動で受け取るもの

再起動の事前入力のために、ブラウザーはジョブの生のフォームデータを受け取ります。このデータには、list の行や YAML のサブフォームの中も含めて、
パスワードは一切含まれないため、ユーザーはパスワードをもう一度入力します。

フォームの依存関係によって非表示になっている password フィールドは不要で、もう一度入力する必要はありません。
