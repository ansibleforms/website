## ワークフローセクション

**デザイナー > ワークフロー** では、ワークフローファイルがファイルエクスプローラーに一覧表示され、どの [デザイナー](../designer/) セクションにもある
YAML、ビジュアル、プレビューのタブがあります。

- ツールバーの **`+` ボタン** で、空のワークフローを含むワークフローファイルを作成します。
- **YAML** は、書かれているとおりのファイルを表示します。コメントとキーの順序は、ほかのタブでも保持されます。
- **ビジュアル** は、ファイル内の各ワークフローをグラフとして描き、その上に名前と説明を表示します。2 つのワークフローを含むファイルでは、
  両方が上下に並んで表示されます。
- **プレビュー** はワークフローのドライランです。 [試してみる](#trying-it-out) を参照してください。

問題はグラフの上に一覧表示され、それぞれにその行の YAML を開くリンクがあります。存在しないノードへのリンク、ループ、デザイナーが
認識していない playbook、インベントリ、認証情報、ランナー、リポジトリなどです。

---

## グラフ

グラフは左から右へ、 **START** から最後のノードへと読みます。各ノードには識別子と、その下に実行するものが表示されます。
リンクは、グラフ内の凡例のとおり、発火の条件によって色分けされています: 成功時、失敗時、
常に。

- **START をクリック** すると、最初のノードを追加します。親のないノードで、ワークフローの開始と同時に実行されます。
- **ノードをクリック** すると、そのノードを編集します。
- **リンクをクリック** すると、発火の条件を変更したり、リンクを削除したりできます。

---

## ノードを追加する

新しいノードはウィザードで追加します。既存のノードで **成功時に新しいノード**、 **失敗時に新しいノード**、 **常に新しいノード** のいずれかを選ぶか、
最初のノードの場合は START を使います。

1. **実行するもの**: ノードの識別子、 **実行するもの** (ノードの種類と、playbook ノードの場合は実行場所)、
   および実行する対象です。playbook、テンプレートまたはジョブ、ワークフロー、承認の名前とタイムアウト、またはリポジトリです。
   [ノードの実行場所](#where-a-node-runs) を参照してください。
2. **実行のしかた**: 実行設定です。インベントリ、認証情報、制限、タグ、詳細度、
   チェックモードと差分モード、条件 ( **実行条件** )、 **値の取得元** です ( [ワークフローファイル](file.html#run-settings) を参照)。
3. **つなぎ先**: このノードがどのノードの後に、どの条件で実行されるかです。

**作成** で、ノードを YAML に追加します。

---

## ノードの実行場所

**実行するもの** では、ノードが何をどこで実行するかを 1 つのリストで指定します: **RTE の playbook**、 **AWX のテンプレート**、 **Semaphore の
テンプレート**、 **Rundeck のジョブ**、 **Jenkins のジョブ**、続いて **ワークフロー**、 **承認**、 **リポジトリの pull** です。

| 実行するもの | その下のフィールド | ランナー |
|---|---|---|
| **RTE の playbook** | **Playbook**: デザイナーの playbook | **デフォルトの RTE**、または名前で指定した RTE ランナー |
| **AWX のテンプレート** (AAP と Ascender を含む) | **テンプレート**: 入力したテンプレートの名前 | AWX ランナー (それぞれの種類付き) |
| **Semaphore のテンプレート** | **テンプレート**: 入力したテンプレートの名前 | Semaphore ランナー |
| **Rundeck のジョブ** または **Jenkins のジョブ** | **ジョブ**: 入力したジョブの名前 | Rundeck または Jenkins のランナー |

- **RTE の playbook** は常に選択できます。それ以外は、インスタンスにその種類の [ランナー](../runners.html) がある場合にだけ選択できます。
- **ランナー** にはその種類のランナーだけが一覧表示され、デフォルトのランナーに印が付いてあらかじめ選択されます (ない場合は名前順で最初のもの)。
- 別の実行場所を選ぶと、ノードが実行するものはクリアされるため、選び直します。
- デザイナーがランナーを認識していないノードには、 **{runner} のテンプレートまたはジョブ** と表示されます。

ワークフローファイルは変わりません。そのようなノードは、 `runner:` を持つ `job_template` ノードです (
[ワークフローファイル](file.html#run-settings) を参照)。

## ノードを編集する

ノードをクリックすると、4 つのタブを持つダイアログが開きます。

| タブ | 内容 |
|---|---|
| **実行するもの** | 識別子、 **実行するもの**、実行する対象、playbook ノードの場合はランナー |
| **実行のしかた** | 実行設定。認証情報はリストから選び、それぞれ `+` で追加します |
| **次の後に実行** | ノードに入るリンクと、 **すべての親の収束が必要** |
| **次に実行** | ノードから出るリンク。 **既存のノードにリンク:** と **新しいノードにリンク:** があります |

**YAML で表示** でそのノードの YAML を開き、 **ノードを削除** でノードをリンクとともに削除します。変更はすべてすぐに
YAML に書き込まれます。 **保存** でファイルを保存します。

---

## 試してみる

**プレビュー** タブでは、何も起動せずに、AWX のルールに従ってワークフローを最後まで再生します。

すべてのノードは成功の状態から始まります。ノードをクリックすると失敗させ、もう一度クリックすると成功に戻します。グラフには、
どのノードが実行され、どのノードが実行されないか、ワークフローが失敗するかどうかが表示されます。 **リセット** で、すべてのノードを再び成功に戻します。
