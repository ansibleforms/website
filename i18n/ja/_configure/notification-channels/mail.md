## メールチャネル

メールチャネルは、アプリがメールを送るサーバーです。SMTP サーバー、または 7.6.0 からは Microsoft 365 です。複数持つことができ、
**既定** の印が付いたものが、フォームがメールチャネルを指定していないときにアプリがメールの送信に使うサーバーです。

| ステップ | フィールド | 意味 |
|---|---|---|
| 認証情報 | 認証情報 | [接続 > 認証情報](../credentials.html) の **smtp** 認証情報（メールサーバー、そのポートと TLS、ログイン）、または [Microsoft 365](microsoft-365.html) 経由で送信するための **Microsoft Entra ID** 認証情報。7.6.0 からは任意です。指定しない場合はチャネル自身のメールサーバーを通じて送信します。下記を参照してください。 |
| 認証情報 | メールサーバー、メールポート、TLS を使用 | 認証情報がない場合のみ。チャネルがログインなしで送信に使うサーバー（リレー）です。この場合 **メールサーバー** は必須です。 |
| 認証情報 | 送信方法 | Microsoft Entra ID 認証情報の場合のみ。 **Microsoft Graph** （既定）または **SMTP (OAuth2)** 。 [Microsoft 365](microsoft-365.html) を参照してください。 |
| 送信者 | 送信元アドレス | 受信者に表示される送信者のアドレス。Microsoft 365 の場合は、メールの送信元となるメールボックスです。 |

## ログインのないリレー

ログインなしでメールを受け付けるメールサーバー（リレー）は二通りの方法で使えます。どちらも認証なしで送信します。

- **サーバーだけを持つ smtp 認証情報** ：その **ユーザー (任意)** と **パスワード (任意)** は空のままにします。
- **認証情報なし** （7.6.0 から）： **認証情報** ステップで、チャネル自身の **メールサーバー** 、 **メールポート** 、 **TLS を使用** を尋ねます。

独自のサーバーを持つ認証情報を指定したチャネルは、それまでチャネルに入力されていたサーバーを破棄します。

## 既定のチャネル

最初のメールチャネルが既定になり、行メニューの **既定にする** で別のチャネルに変更できます。メールチャネルのページの **詳細** タブにある
**既定** スイッチも同じ働きをします。

7.6.0 からは、既定のメールチャネルがない間、または既定のものがオフになっている間、アプリはメールをまったく送信しません。以前は設定ページ
または構成シードのメール設定が代わりに使われていました。7.6.0 へのアップグレードでは、有効なメールチャネルがまだない場合、これらの設定が
既定のメールチャネル `default` になります。ログインがある場合は新しい smtp 認証情報 `mail-login` を指定し、リレーの場合は独自のサーバーを
持ち、認証情報はありません。 [構成シード](../seed/) では、 `notification_channels:` の下にメールチャネルを宣言してください（
[例](../seed/example.html) を参照）。 `settings:` の下の古い `mail_*` キーも引き続き動作しますが、非推奨です。
