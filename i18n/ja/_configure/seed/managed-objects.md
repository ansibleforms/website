## 単一行のセクションはすべてか無しか

`ldap` 、 `settings` 、 `chat_assistant` （7.8.0 より前は `chat` ）はそれぞれ **単一行** なので、シードはそのすべてのフィールドを宣言する必要があります。

フィールドを省いたシードは起動を拒否し、そのフィールドの名前を示します。

```
Config seed failed, refusing to start: Seed file validation failed: /settings must have required property 'url'
```

空の値は `""` または `false` で明示的に宣言します。いくつかのフィールドは任意で、省いた場合は変更されません。

| セクション | 任意のフィールド |
|---|---|
| `ldap` | `description` 、 `credential` （バインドに使う認証情報）、 `groupfilter` |
| `chat_assistant` | `auth_type` 、 `api_version` 、 `request_user` 、 `ignore_certs` 、 `extra_headers` 、そして 7.8.0 からは `credential` |
| `settings` | `mail_*` キー。7.6.0 から非推奨です（ [例](example.html) を参照） |

`settings` が対象とするのは URL と、非推奨のメールのキーだけです。ほかの設定はすべて編集可能なままです。

## ファイルはシークレットを持たない

各 `${VARIABLE}` はその環境変数（Kubernetes では `Secret` から）で置き換えられるので、ファイルは Git に置けます。

設定されていない変数は **致命的なエラー** になるので、プレースホルダーがパスワードとして保存されてしまうことは決してありません。

認証情報は [シークレットストア](../secret-stores) （ `secret_store` 、 `secret_ref` ）も使えます。 `vault_path` は 8 で削除されます。

## 管理対象オブジェクト

リストのセクション（ `runners` 、 `secret_stores` 、 `credentials` 、 `databases` 、 `sso` 、 `repositories` 、 `syslog` 、
`notifications` 、 `labels` ）または単一行のセクションのオブジェクトで、シードから来たものには **管理対象** のフラグが付きます。

- **起動のたびに** 適用されるので、ファイルが正であり続けます。
- 読み取り専用です。API は **403** を返し、インターフェースでは編集と削除が無効になり、そのページには構成
  シードファイルから来ていて読み取り専用であることが表示されます。
- フラグを設定または解除できるのはシードだけです。

手動で作成したオブジェクトは、シードが同じ名前を宣言しない限り **決して変更されません** 。宣言した場合、そのレコードは **引き継がれ** 、
宣言したフィールドが適用されて読み取り専用になります。引き継ぎは警告としてログに記録され、監査証跡にも残ります。

シードの適用はべき等です。すでに一致しているレコードはそのまま残るので、再起動では通常 `0 updated` と報告されます。

作業ツリーがない宣言済みのリポジトリは、起動のたびに **再びクローンされる** ので、最初のクローンが失敗しても
再試行されます。ステータスページの *リポジトリ* の行には、作業ツリーのないリポジトリが表示されます。

7.8.0 からは、 [git リポジトリ](../repositories/) も同じ種類のオブジェクトを保持できます。リポジトリが保持するオブジェクトはリポジトリのものの
ままです。そのオブジェクトに対するシードの項目は適用されず、サーバーログにそう記録されます。シードが宣言するリポジトリはシードのものの
ままです。

### オブジェクトの削除

ファイルからオブジェクトを削除すると、それは **解放** されます。レコードは残り、再び編集可能になります。セクション全体を削除しても
同じです。

ファイルがもう宣言していない管理対象のレコードを **削除** するには、リストのセクションに `prune: true` を追加します。

```yaml
credentials:
  prune: true
  items:
    - name: production-db
      # anything else the seed used to manage is deleted
```

`prune` が手動で作成したレコードを削除することはありません。

### シードをオフにする

`CONFIG_SEED_PATH` の設定を外すとシードはオフになります。次回の起動で、適用された空のシードと同じように、シードが管理していたすべての
レコードとフィールドが解放されます。レコードは値を保ったまま再び編集可能になり、サーバーログと監査ログに解放されたものが記録されます。

ファイルが存在しない `CONFIG_SEED_PATH` では何も解放されません。マウントされたファイルは遅れて現れるだけかもしれないので、
サーバーは代わりに起動を拒否します。

## シードが宣言する設定

7.8.0 で追加されたセクションは、管理対象オブジェクトほど厳格には所有されず、所有のしかたは二通りです。

| セクション | シードによる所有のしかた |
|---|---|
| `defaults` 、 `logo` 、 `icon` 、 `name` 、 `links` 、 `mcp` | フィールドごと：宣言した各フィールドはそのページで通知とともに読み取り専用になり、API はその変更を拒否します（403） |
| `users` 、 `groups` 、 `announcements` 、 `disclaimer` 、 `ssh` | 適用のたびに作成または変更され、ロックも削除もされません |

シードが宣言しなくなった `defaults` 、 `logo` 、 `icon` 、 `name` 、 `links` 、 `mcp` のフィールドは解放され、シードをオフにすると
すべてが解放されます。シードのロゴやアイコンは、アプリでアップロードも削除もできません。リポジトリが同じページを保持している場合、
シードは宣言したフィールドを保ち、リポジトリはほかのフィールドを保持します。

シードのユーザー、グループ、お知らせ、免責事項のバージョン、SSH の鍵と既知のホストはアプリで編集可能なままで、次の適用で
異なる部分にシードの値が再び書き込まれます。ファイルから項目を削除してもアプリには残り、 `prune` はそのどれも削除しません。
