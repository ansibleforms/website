# 認証情報ページ
{: .no_toc }

認証情報のリストと、認証情報を追加するダイアログ
{: .fs-6 .fw-300 }

**接続 > 認証情報** のページには、すべての認証情報が **名前** 、 **種類** 、 **説明** 、 **使用元** とともに表示されます。使用元は、
その認証情報を指定しているレコード、フォーム、ワークフローの数です（ [使用中の認証情報](../credentials.html#credentials-in-use) を参照）。

**認証情報を追加** を押すと、ステップ形式のダイアログが開きます。

| ステップ | フィールド |
|---|---|
| 認証情報 | 名前と説明。どちらも必須です。 |
| 種類 | 18 種類のいずれか。下記を参照。 |
| 保存先 | ユーザーとパスワードの保存場所：**データベース**（AnsibleForms のデータベースで暗号化）または **シークレットストア**。**シークレットストア** では、**キーを指す** はすでにストアにあるシークレットを読み取り、**キーに書き込む** は **ログイン** ステップで入力したユーザーとパスワードを **保存** 時にストアへ書き込みます。次にストアを選び **参照** を入力します。例はストアに合わせて HashiCorp Vault のパスか CyberArk のアカウントになります。シークレットストアのログインに使う CyberArk と HashiCorp Vault には使えません。 |
| ログイン | その種類が何を使ってどこにログインするか。下記を参照。 |

**種類** ステップには、種類が名前で表示されます。AAP、API、Ascender、AWX、CyberArk、データベース、Git、HashiCorp Vault、Jenkins、LDAP、
Microsoft Entra ID、Open ID、RTE、Rundeck、Semaphore、SMTP、SSH、ユーザーとパスワードです（ [認証情報の種類](types.html) を参照）。

**ログイン** ステップには、アドレスを含め、その種類のすべてのフィールドがあります。接続用の別のステップはありません。7.6.0 からは、
一部の種類でまずサインイン方法を尋ね、それに必要なものだけを表示します（ [認証情報のサインイン方法](types.html#how-a-credential-signs-in) を参照）。

| 種類 | ログインステップのフィールド |
|---|---|
| CyberArk 以外のすべての種類 | パスワード、またはその代わりになるもの。LDAP の **パスワード** （バインドパスワード）、Entra ID と Open ID の **クライアントシークレット** 、HashiCorp Vault と RTE の **トークン** 、Semaphore、Rundeck、Jenkins の **API トークン** 、AWX、AAP、Ascender、Git の **トークン** または **パスワード** 。SSH の秘密鍵、SMTP のリレー、Entra ID の証明書では不要 |
| HashiCorp Vault、RTE、Semaphore、Rundeck 以外のすべての種類 | ユーザー。CyberArk の AppID、LDAP のバインド DN、Entra ID と Open ID のクライアント ID。 **トークン** （AWX、AAP、Ascender、Git）や **ログインなし** （SMTP）では不要 |
| SSH、データベース | **ホスト** と **ポート** 。データベースの場合は **エンジン** と **データベース** も |
| SSH | 7.6.0 から **ログイン方法** ： **パスワード** 、または **秘密鍵** （ **秘密鍵** と任意の **パスフレーズ** ） |
| AWX、AAP、Ascender、Git | 7.6.0 から **サインイン方法** ： **トークン** （ユーザーなし）または **パスワード** （ユーザーとそのパスワード） |
| ユーザーとパスワード、API | 7.6.0 から、パスワードの後の **ホストとポートを追加** スイッチで、任意の **ホスト** と **ポート** を表示 |
| SMTP | **メールサーバー** （必須）、 **メールポート** 、 **TLS を使用** 。7.6.0 から **サインイン方法** ： **ログインなし** （リレー）または **ログイン** （ユーザーとそのパスワード） |
| LDAP | ディレクトリの **サーバー** （必須）、その **ポート** と **TLS を有効にする** 。TLS の場合は **証明書を無視** 、 **CA バンドル** 、 **クライアント証明書** |
| Microsoft Entra ID | **テナント ID** （必須）と **リダイレクト URI** 。7.6.0 からは **サインイン方法** で **シークレット** （ **クライアントシークレット** ）または **証明書** （ **証明書** とその秘密鍵、メールのみ）を選びます |
| Open ID | **発行者 (Issuer)** （必須）と **リダイレクト URI** |
| HashiCorp Vault、CyberArk、RTE、AWX、AAP、Ascender、Semaphore、Rundeck、Jenkins | ログイン先のアドレスである **サーバー** （必須）と、 **証明書の検証をスキップ** 、 **CA バンドル** |
| CyberArk | **クライアント証明書** と **クライアントキー** |

**キーを指す** を選ぶと、ユーザーとパスワードは尋ねられません。ストアがそれらを渡します。**ログイン** ステップには種類のアドレス項目（SSH、データベース、メールとディレクトリのサーバー、サーバーのアドレス、7.6.0 からはユーザーとパスワードと API の任意のホストとポート）だけが残り、Git のログインには **ログイン** ステップがなく、**保存先** ステップから保存されます。

**キーに書き込む**（7.6.0 以降）では、**ログイン** ステップでユーザーとパスワードを尋ね（パスワードを使うサインイン方法だけを表示します。[認証情報のサインイン方法](types.html#how-a-credential-signs-in) を参照）、**保存** でストアの **参照** に書き込みます。AnsibleForms はストアと参照だけを保持します。書き込みを許可するストアだけが表示され、**シークレットストアを追加** は書き込みがオンの状態でストアを作成します。すでにシークレットがあるキーは **既にあるシークレットを上書きする** にチェックしたときだけ置き換えられます。[認証情報の書き込み](../secret-stores/#writing-credentials) を参照してください。

行をクリックすると、その認証情報のページが開きます。行メニューには **編集** 、 **接続テスト** （データベースの認証情報のみ）、 **削除** があります。
パスワードは認証情報のページの **ログイン** タブで変更します。
