# 認証情報のページ
{: .no_toc }

認証情報のタブと、それを使っているもの
{: .fs-6 .fw-300 }

認証情報のページには、ダイアログのステップがタブとして表示され、さらにそれを使っているものも表示されます。

| タブ | 内容 |
|---|---|
| 詳細 | 名前と説明。 |
| 種類 | 認証情報の用途。 |
| ログイン | ダイアログの **ログイン** ステップと同じく、その種類のすべてのフィールド。ユーザー、パスワード、ログイン先（ホストとポート、データベース、メールサーバー、ディレクトリのサーバー、テナントまたは発行者、サーバーのアドレスとその TLS）。CyberArk 認証情報の場合は AppID、クライアント証明書、キー。7.6.0 からは、サインイン方法の選択と、SSH 認証情報の秘密鍵とパスフレーズ。 |
| 保存先 | データベースまたはシークレットストアと、ストアおよび参照。CyberArk と HashiCorp Vault にはありません。 |
| 使用元 | この認証情報を指定しているすべてのもの。シークレットストア、通知チャネル、リポジトリ、LDAP ディレクトリ、SSO プロバイダー、ランナー、 [データベース](../databases.html) （7.5.0 から）、チャットアシスタント、フォーム、デザイナーのワークフロー。行をクリックすると開きます。 |

パスワードは **ログイン** タブで入力し、一度保存すると二度と表示されません。空のままにすると、保存されているものが残ります。CyberArk
認証情報のクライアントキーも同様で、7.6.0 からは SSH 認証情報の秘密鍵とパスフレーズも同様です。

7.6.0 からは、これはサインイン方法が変わらない間だけです。変えた場合（SSH の **秘密鍵** から **パスワード** とその逆、SMTP の
**ログインなし** から **ログイン** 、Entra ID の **証明書** から **シークレット** とその逆、 **トークン** から **パスワード** とその逆）、
保存されているものは使えません。必要な新しいシークレットが必須になり、 **保存** 時に求められます。 **パスワード** に変えた SSH 認証情報は、
選択の下に表示されるとおり、 **保存** 時に保存済みの秘密鍵とパスフレーズを破棄します。 **保存先** タブで **キーに書き込む** を選ぶと、
パスワードを使う選択だけが表示されます。 [認証情報のサインイン方法](types.html#how-a-credential-signs-in) を参照してください。

右上には **接続テスト** （データベースの認証情報のみ）、 **削除** 、 **保存** があります。

7.3.0 からは、 **使用元** に何かが表示されている間は **削除** と新しい名前は拒否されます。 [使用中の認証情報](../credentials.html#credentials-in-use) を参照してください。

[構成シード](../seed/) で宣言された認証情報は、このページでは読み取り専用です。代わりにシードファイルで変更してください。
