# AnsibleForms とは
{: .no_toc }

Ansible と AWX の前に置くセルフサービスのフォームと、それが必要になる場面
{: .fs-6 .fw-300 }

1. TOC
{:toc}

---

## できること

AnsibleForms は、プレイブック、ワークフロー、または AWX、AAP、Ascender、Semaphore、Rundeck、Jenkins のテンプレートやジョブの前に
Web フォームを置き、コマンドラインを使わずに自動化を実行できるようにします。

フォームは入力を集めてチェックし、extravars の形に整えてジョブを起動します。フォームのデータは、データベース、
REST API、ファイル、ほかのフィールドから取得でき、すべての起動はその出力とともにジョブ履歴に記録されます。

---

## 代表的な使い方

チームは AnsibleForms を使い、定型的な自動化を、それを依頼する人に任せています。

* **セルフサービスの依頼** : 仮想マシン、ストレージボリューム、共有、ユーザーアカウントを、依頼者自身が入力します
* **保護された操作** : 承認ポイント付きの操作で、ジョブが実行される前に別の人が承認します
* **データに基づく選択** : CMDB、データベース、REST API から埋めたドロップダウンを、フィールドからフィールドへ連動させます
* **定期的なジョブ** : 後で、または cron のスケジュールで実行するフォームで、毎回同じように検証された入力を使います
* **ツールとエージェントのための自動化** : REST API、MCP サーバー、チャットアシスタントが同じフォームを起動します

## AnsibleForms か、AWX のサーベイか

AWX、AAP、Ascender には独自のサーベイがあります。どちらが合うかは、ジョブを起動する人に何が必要かによります。

次のような場合は **サーベイ** で十分です。

* 質問が固定されている。テキスト、数値、パスワード、静的なリストからの選択
* ユーザーがすでに AWX、AAP、Ascender で作業しており、その権限で間に合う
* アプリケーションとデータベースをもう 1 つ運用・保守したくない

次のような場合は **AnsibleForms** が役立ちます。

* 選択肢がほかの場所から来る。データベース、REST API、ファイル、ほかのフィールド（連動するドロップダウン）
* プレイブックに届く前に、入力に検証、構造（リスト、ネストしたオブジェクト）、計算された値が必要
* ジョブに承認ポイント、スケジュール、または 1 つのフォームからプレイブック、テンプレート、承認をつなげるワークフローが必要
* ユーザーに AWX をまったく見せたくない、または AWX なしでもプレイブックを実行する

AnsibleForms は AWX、AAP、Ascender のテンプレートを起動するので、両者は一緒に使えます。フォームが入力を集めて整え、
AWX は引き続きジョブを実行します。
