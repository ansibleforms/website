## フォームの操作

フォームはすぐに実行する以外のこともできます。 **送信** ボタンの横のドロップダウンには、さらに 3 つの操作があります。

| 操作 | 内容 | ロールオプション |
|---|---|---|
| **スケジュール (定期実行)** | cron 式に従ってフォームを実行するスケジュールを作成します | `allowScheduledJobs` |
| **後で実行 (1 回限り)** | 選んだ日時にフォームを 1 回だけ実行するスケジュールを作成します | `allowPlannedJobs` |
| **データを保存** | フィールドの値を保存し、後でフォームに再び読み込めるようにします | `allowStoredJobs` |

ロールオプションがオフの操作は表示されません。どの操作でも、 **送信** と同じように事前にフォームが検証されます。
2 つのスケジュール操作は **ジョブ > スケジュール済み** に項目を作成し、 **データを保存** は **保存済みジョブ** ページに項目を作成します。
[ジョブ](./) ページのサイドバーでは、 **未来** の下の **スケジュール済み** と **保存済み** からこれらを開けます。ロールオプションについては
[ロールオプション](../config/roles.html#role-options) で説明しています。

{: .warning }
> `allowScheduledJobs` は管理者レベルのオプションとして扱ってください。このオプションで作成したスケジュールは、作成したユーザーの所有にはなりません。このオプションを
> 持つすべてのユーザーが、すべてのスケジュールを表示し、変更できます。また、そのようなスケジュールは、作成者自身のアクセス権にかかわらず、どのフォームでも
> 管理者権限で実行されます。管理者として信頼できるロールにだけ付与してください。

{: .note }
> **後で実行 (1 回限り)** に必要なのは `allowPlannedJobs` だけです。 `allowScheduledJobs` を持たないユーザーの場合、 **そのユーザーとして** 実行を
> 予定します。サーバーはそのユーザーがフォームを実行できるかをチェックし、時刻になるとジョブはそのユーザーとして、そのユーザーの所有で実行されます
> ( [予定された実行](#planned-runs) を参照)。

## フォームをスケジュールする

フォームに入力してから、 **送信** の横のドロップダウンを開き、スケジュール操作のいずれかを選びます。

- **スケジュール (定期実行)** は **スケジュールを作成** を開きます。 **名前** と **cron 式** (既定値の `0 0 * * *` は
  毎日午前 0 時に実行) を入力し、 **スケジュールを作成** を選びます。
- **後で実行 (1 回限り)** は **後で実行** を開きます。 **名前** を入力して **実行日時** を選び、
  **ジョブをスケジュール** を選びます。

名前はすべてのスケジュールの中で一意である必要があります。スケジュールには、フォームの名前と、その時点でフォームが生成した extravars のコピーが
YAML で保存されます。毎回の実行ではそのコピーが使われるため、ジョブが受け取る内容を変えるにはスケジュールのページで編集してください。
代わりに rrule でタイミングを決めたり、終了を設定したりするには、そのページを開いて **スケジュール** タブを変更します。

## スケジュールの一覧

**ジョブ > スケジュール済み** にはすべてのスケジュールが一覧表示され、 `allowScheduledJobs` が必要です。行を選ぶとそのスケジュールのページが開きます。

| 列 | 表示内容 |
|---|---|
| **有効** | スケジュールが自身のタイミングで実行されるかどうか |
| **名前** と **フォーム** | スケジュールと、それが実行するフォーム |
| **スケジュール** | タイミングをわかりやすい言葉で表したもの ( *At 02:00 AM* など)。ポイントすると cron やルールそのものが表示されます |
| **最終実行** | 最後に実行された日時 |
| **次回実行** | 次に実行される日時。今後の実行がない場合はダッシュ |
| **ステータス** | 前回の起動: ジョブを開始したかどうか、または起動中は **開始中…** |

**スケジュール** 列では、1 回限りのスケジュールは **1 回限りの実行** と表示されます。言葉で説明できない rrule は
そのまま表示されます。各行のメニューには次の操作があります。

| 操作 | 内容 |
|---|---|
| **編集** | スケジュールのページを開きます |
| **今すぐ実行** | タイミングを待たずに、スケジュールを今すぐ実行します |
| **有効にする** または **無効にする** | **有効** 列の表示に応じて、スケジュールをオンまたはオフにします |
| **削除** | スケジュールを削除します。すぐに実行されなくなります |

**新しいスケジュール** では、3 つのステップでスケジュールを一から作成します。 **詳細** ( **名前** 、 **説明** 、 **フォーム** )、
**スケジュール** (タイミングと終了)、 **Extra vars** です。 **Extra vars** は入力用のフォームがない YAML なので、
playbook に必要な値を自分で、ディクショナリ (key: value のペア) として追加してください。

## スケジュールのページ

スケジュールのページには、ダイアログのステップがタブとして並び、右上に **今すぐ実行** 、 **削除** 、 **保存** があります。

| タブ | 内容 |
|---|---|
| **詳細** | ソース、 **名前** 、 **説明** 、 **フォーム** 、続いて **前回の起動** 、 **開始したジョブ** 、 **最終実行** 、 **次回実行** 、 **有効** |
| **スケジュール** | タイミング ( [スケジュールのタイミング](#timing-a-schedule) を参照) と終了のしかた ( [スケジュールの終了](#the-end-of-a-schedule) を参照) |
| **Extra vars** | ジョブが受け取る YAML。git で管理されるスケジュールでは、そのファイルのプロンプトも |
| **実行** | 開始したジョブ (新しい順)。行を選ぶとジョブが開きます |

**前回の起動** は、前回の起動がどうだったかをステータスで示します。失敗した場合は、ポイントするとその理由が表示されます。 **開始したジョブ** は
開始したジョブへのリンクで、開いてどう終了したかを確認できます。 **実行** タブには、表示できるジョブが、実行ユーザー、
開始、終了、所要時間、ステータスとともに一覧表示されます。件数はタブのタイトルに表示されます。

**有効** スイッチを使うと、スケジュールを削除せずに一時停止でき、ページの他のフィールドと同じく **保存** で保存されます。
オフにしたスケジュールは設定とともに一覧に残りますが、自動では実行されません。定期実行のスケジュールは実行をスキップし、1 回限りのスケジュールは
その時刻を過ぎても、再びオンにされるまで待機します。 **今すぐ実行** では引き続き必要に応じて実行できます。新しいスケジュールはオンで作成されます。

## スケジュールのタイミング

スケジュールのタイミングは 3 つの方法から、 **スケジュール** タブの **タイミング** で選びます。rrule は 7.8.0 の新機能です。

| タイミング | 実行 | 参照 |
|---|---|---|
| **Cron** | 定期実行、サーバーのタイムゾーンでの cron 式 | [cron 式とタイムゾーン](#cron-expressions-and-time-zone) |
| **繰り返しルール (rrule)** | 定期実行、独自のタイムゾーンでの iCal ルール | [繰り返しルール](#recurrence-rules) |
| **1 回限りの実行** | 指定日時に 1 回 | [スケジュールの実行のしくみ](#how-a-schedule-runs) |

cron または rrule では、エディターが次の 3 回の実行を表示し、スケジュールの終了以降は表示しません。タイミングを変更すると、
選んだものだけが残ります。cron から rrule に切り替えたスケジュールは、その cron を失います。

---

## cron 式とタイムゾーン

定期実行のスケジュールには、標準的な 5 フィールドの cron 式を指定できます: 分、時、日、月、曜日です。

| 式 | 実行タイミング |
|---|---|
| `*/15 * * * *` | 15 分ごと |
| `0 2 * * *` | 毎日 02:00 |
| `30 7 * * 1-5` | 月曜日から金曜日の 07:30 |
| `0 0 1 * *` | 毎月 1 日の午前 0 時 |

cron エディターは式を言葉で説明し、プリセットを提供し、次回以降の実行をプレビューします。サーバーは、実行できない式や、
決して発生しない式を拒否します。その他の例と、エディターが受け付けない cron の機能については、FAQ の
[どの cron 式を使えますか?](../faq.html#which-cron-expressions-can-i-use) を参照してください。

{: .note }
> cron スケジュールは、プロフィールやブラウザーのタイムゾーンではなく、 [`LOG_TZ`](../customization/logging.html#env_LOG_TZ) (既定は `UTC` ) で設定した
> サーバーのタイムゾーンで実行されます。cron エディターも、同じタイムゾーンで次回以降の実行をプレビューします。

## 繰り返しルール

7.8.0 以降、定期実行のスケジュールには代わりに iCal の繰り返しルール (rrule) を指定でき、独自のタイムゾーンで実行されます。

```text
DTSTART;TZID=Europe/Brussels:20261020T020000 RRULE:FREQ=DAILY;INTERVAL=1
DTSTART:20261019T060000Z RRULE:FREQ=WEEKLY;INTERVAL=1;BYDAY=MO
DTSTART;TZID=America/New_York:20261101T073000 RRULE:FREQ=MONTHLY;INTERVAL=1;BYDAY=MO,TU,WE,TH,FR;BYSETPOS=-1
```

1 つ目はブリュッセル時間で毎日 02:00、2 つ目は UTC で毎週月曜日の 06:00、3 つ目はニューヨーク時間で毎月最後の平日の 07:30 に
実行されます。ルールは 1 行で、各部分はスペースで区切ります。

| 部分 | 内容 |
|---|---|
| `DTSTART` | 最初の実行。 `TZID` ( `Europe/Brussels` のような IANA タイムゾーン、または `UTC+5` や `GMT-3` のようなオフセット) 付き、または `Z` で終わる UTC |
| `RRULE` | 繰り返し方: 1 以上の `INTERVAL` を伴う `FREQ` 、必要に応じて `BYDAY` 、 `BYHOUR` 、 `BYMONTHDAY` 、 `COUNT` 、 `UNTIL` …。1 つ以上 |
| `EXRULE` | 任意: スキップする実行のルール |

サーバーは実行できないルールを拒否し、その理由を示します。

- `DTSTART` がない、複数ある、またはタイムゾーンのないもの、そして `EXDATE` や `RDATE` 。
- `INTERVAL` のないルール、 `FREQ=SECONDLY` 、数値付きの `BYDAY` ( `5MO` )、または `COUNT` と `UNTIL` の併用。
- 999 を超える `COUNT` 、範囲外の `BYxxx` の数値 ( `BYHOUR` は 0 から 23、 `BYSETPOS` は 1 から 366 または -366 から -1 …)、曜日でない
  `WKST` 、実在しない日付の `DTSTART` や `UNTIL` ( `20300230` )、または 1 つのルール内で 2 回指定された部分。
- 決して発生しないルール: `DTSTART` から 50 年以内に実行がないもの。たとえば午前 0 時からの `FREQ=HOURLY;INTERVAL=2;BYHOUR=1` は、
  偶数時にしか当たりません。

エディターはテキストボックスです。新しい rrule は、ブラウザーのタイムゾーンで毎日午前 0 時から始まります。ルールが拒否される場合はその理由をすぐに示し、
そうでなければ次の 3 回の実行をルール自身のタイムゾーンで表示します。 `UNTIL` や `COUNT` が過ぎている場合は **この rrule には今後の実行がありません。** と表示します。
夏時間の切り替えで飛ばされる時刻は、時計がその時刻に達したときに実行されます (時計が 02:00 から 03:00 に進む夜、02:30 は 03:30 に実行)。
これは cron と同じです。時計が 2 回示す時刻は、1 回目に 1 回だけ実行されます。

## スケジュールの終了

7.8.0 以降、cron または rrule でタイミングを決めたスケジュールには終了を設定できます。 **スケジュール** タブの **終了** で 1 つを選びます。

| 終了 | スケジュールが終了するとき |
|---|---|
| **なし** | 終了しません。既定値で、7.8.0 より前のすべてのスケジュールもこれです |
| **日付で** | 選んだ日時。それ以降は実行されません |
| **実行** … **回後** | 合計でその数のジョブ ( **実行** タブに一覧表示されるもの) を開始したとき。フィールドにはこれまでの数が表示されます |

**終了時** には、スケジュールはオフになる ( **無効にする** 、既定値) か、削除されます ( **削除する** )。 **スケジュールの終了**
システムタスクが毎分終了を適用し、実行回数に達したスケジュールは最後の実行の直後に終了します。rrule 自身の
`UNTIL` や `COUNT` も引き続き適用され、終了はそれに加えて適用されます。

1 回限りのスケジュールには終了がなく、実行とともに終わります。 **実行後に削除** スイッチは既定でオンで、実行後にスケジュールを削除します。
オフにすると、スケジュールは実行後に無効になり、その結果とともに残ります。

## スケジュールの実行のしくみ

スケジュールの時刻になるとキューに入れられ、サーバーは 10 秒ごとにキューを確認して、キューにあるスケジュールを 1 つずつ開始します。

- **定期実行** のスケジュールは、前回の実行がまだキューにあるか実行中の場合はその実行をスキップするため、実行が重なることはありません。
- **1 回限り** のスケジュールはその時刻から 1 分以内に実行され、その後削除されます ( **実行後に削除** がオフの場合は、オフにされて
  残ります)。 **今すぐ実行** で開始した場合も同じです。
- **ステータス** は、ジョブが開始された場合は `success` 、開始できなかった場合は `failed` です。 `success` はジョブが
  起動されたことを示すだけなので、どう終了したかはジョブを開いて確認してください。

`allowScheduledJobs` で作成したスケジュールは、組み込みユーザー `Schedule Service` (種類 `schedule` ) として
`admin` ロールで実行されます。スケジュールを作成した人のアクセス権にかかわらずどのフォームでも実行でき、extravars の
`ansibleforms_user` はこのユーザーを表します。 [予定された実行](#planned-runs) は、代わりに予定したユーザーとして実行されます。

ジョブには `schedule` オブジェクトも渡されるため、playbook はスケジュールによって開始されたことがわかります。

```yaml
schedule:
  id: 3
  name: Nightly cleanup
  description: ''
  form: Cleanup servers
  one_time_run: null
```

`one_time_run` は 1 回限りのスケジュールの実行時刻で、定期実行のスケジュールでは `null` です。 `enabled` や `repository` などのスケジュールの
他の設定も含まれ、 `run_at` もあります。これは同じ時刻を 7.8.0 より前の名前で示したものです (非推奨、8 で削除)。

## 予定された実行

`allowScheduledJobs` を持たないユーザーが **後で実行 (1 回限り)** を使うと、予定された実行が作成されます。これはそのユーザーに結び付いた 1 回限りのスケジュールです。

- **予定したとき**、サーバーはそのユーザーがフォームを実行できるか (フォームの `roles` ) をチェックします。詳細モードには
  `allowVerboseMode` が必要です。予定された実行は常に 1 回限りで、cron 式や rrule は拒否されます。
- **起動時の検証が `enforce` の場合**、予定した時点でフィールドの値がチェックされるため、拒否される実行は、
  ユーザーがまだ画面を見ている間に拒否されます。
- **実行されるとき**、ジョブはそのユーザーとして、そのユーザーの所有で、ブラウザーからの起動と同じチェックを経て実行されます。
  その時点でのフォームのロール、予約済みの extravars の除去、起動時の検証です。 `ansibleforms_user` はそのユーザーを表します。

予定したユーザーには、 `allowScheduledJobs` が必要な **ジョブ > スケジュール済み** は表示されません。ジョブは自分のジョブ履歴に表示されます。
予定された実行は、実行後に必ず削除されます。

## フォームが変更された場合

スケジュールは名前でフォームを参照し、実行のたびに、その時点で定義されているとおりにフォームを実行します。

- **フォームが編集された場合**: 次回の実行では、新しい定義 (playbook、テンプレート、インベントリ) が、スケジュールに保存された
  extravars とともに使われます。フォームは描画されないため、フィールドは再計算されません。それに合わせてスケジュールの extra vars を編集してください。
- **フォームの名前が変更された、または削除された場合**: 実行は失敗し、 **ステータス** は `failed` になり、 **前回の起動** をポイントすると
  `Failed to launch : No such form '<name>'` と表示されます。スケジュールを編集して正しいフォームを選ぶか、削除してください。

## ジョブ履歴でのスケジュールされたジョブ

スケジュールの実行ごとに通常のジョブが作成され、 [ジョブ](./) ページに、ユーザーを `Schedule Service` として、
予定された実行の場合は予定したユーザーとして一覧表示されます。

`Schedule Service` のジョブはスケジュールを作成した人のものではないため、管理者と `showAllJobLogs` を持つユーザーにしか
表示されません。予定された実行のジョブは、そのユーザーにも表示されます。スケジュールの **実行** タブには開始したジョブが一覧表示され、
**開始したジョブ** は最後のジョブへのリンクです。

## git リポジトリのスケジュール

7.8.0 以降、スケジュールは git リポジトリにも、その YAML ファイルの `controller_schedules:` リストの項目として保存できます。

**スケジュール** の用途を持てるリポジトリは 1 つまでです。その項目はプルのたびに **ジョブ > スケジュール済み** に読み込まれ、
`cron` 、 `rrule` 、 `one_time_run` のいずれかでタイミングが決まります。アプリで作成または変更したスケジュールはそのファイルに書き戻され、
リポジトリのプッシュを待ちます。このようなスケジュールのページにはそのファイルが表示され、終了時は常にオフになるだけです。
[Git リポジトリ](../repositories/) を参照してください。

## API で

7.8.0 以降、API のスケジュールには 3 つのタイミングフィールドがあり、そのうちちょうど 1 つを設定します: `cron` 、 `rrule` 、 `one_time_run` です。

| フィールド | 内容 |
|---|---|
| `cron` | cron 式 |
| `rrule` | 1 行の繰り返しルール |
| `one_time_run` | 1 回の実行の時刻。オフセットまたは `Z` 付きの ISO 8601 の時刻 ( `2026-11-15T22:00:00+01:00` ) |
| `ends` 、 `end_at` 、 `end_count` 、 `end_action` | 終了: `never` 、 `date` 、 `count` のいずれか、その日付、実行回数、そして `disable` または `remove` |
| `remove_after_run` | 1 回限りのスケジュール: `false` にすると、実行後もオフにして残します |

{: .warning }
> 7.8.0 より前に API が受け付けていた組み合わせ、 `run_at` を伴う `one_time_run: true` は、7.8.0 から非推奨で、8 で削除されます。
> 引き続きその時刻の `one_time_run` として読み取られ、サーバーログに警告が出ます。cron を伴う `one_time_run: false` は、その cron として読み取られます。
