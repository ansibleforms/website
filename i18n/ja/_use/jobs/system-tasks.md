# システム処理
{: .no_toc }

AnsibleForms が自動で実行するメンテナンス処理と、その実行タイミング
{: .fs-6 .fw-300 }

1. TOC
{:toc}

---

管理者向け：クリーンアップ、夜間バックアップ、その他のサーバーのバックグラウンド処理です。7.8.0 から **ジョブ** の下に一覧表示されます。

---

## 処理の一覧

サーバーはこれらの処理を自動で実行します。それぞれ、 [`LOG_TZ`](../customization/logging.html#env_LOG_TZ) で設定するサーバーのタイムゾーンの cron で動きます。

| 処理 | 既定の実行タイミング | 内容 |
|---|---|---|
| **放棄されたジョブ** | 1 時間ごと | 出力のないまま 1 日実行され、どのランナーも引き継がなかったジョブを終了します（ [放棄されたジョブ](cleanup.html#abandoned-jobs) を参照） |
| **停止したノード** | 1 分ごと | 応答しなくなった AnsibleForms のノードと RTE が保持していたジョブ、クレーム、ランナーを解放します |
| **スケジュールの終了** | 1 分ごと | 終了に達した [スケジュール](schedules.html) をオフにするか削除します |
| **スケジュール再同期** | 5 分ごと | 変更通知を取りこぼした場合に備えて、スケジュールとリポジトリのプルをデータベースから読み直します |
| **期限切れトークン** | 毎日 03:00 | 期限切れのサインイントークン、トークン失効情報、API トークンを削除します |
| **監査ログの整理** | 毎日 03:30 | `AUDIT_RETENTION_DAYS` より古い監査エントリを削除します |
| **ジョブの整理** | 毎日 02:30 | `JOB_RETENTION_DAYS` より古い終了済みのジョブを、その出力とともに削除します |
| **夜間バックアップ** | 毎日午前 0 時 | データベースをバックアップし、 `NIGHTLY_BACKUP_RETENTION` を超える最も古い夜間バックアップを削除します |
| **保存済みジョブの整理** | 毎日 04:00 | 有効期限を過ぎた、または `STORED_JOB_UNUSED_DAYS` のあいだ使われていない保存済みジョブを削除し、1 日いないノードを忘れます |
| **構成シードの再読み込み** | 1 分ごと | ファイルが変わったときに [構成シード](../seed/reloading.html) を再適用します |

保持期間の設定は [バックアップと保持期間](../customization/retention.html) に、バックアップは [バックアップ](../production/backups.html)
に説明があります。 **構成シードの再読み込み** は [`CONFIG_SEED_PATH`](../customization/configuration.html#env_CONFIG_SEED_PATH) がなければオフです。

これらの処理は、バックグラウンド処理を行うノードで実行されます。 `AF_ROLE` のないプロセス、またはアプリが複数のノードに
分かれている場合はワーカーロックを持つ `worker` です（ [スケーリング](../production/scaling.html#roles) を参照）。

## ランナーハブのループ

ランナーハブはジョブを RTE に渡します。その三つのループは、cron ではなく数秒ごとに実行されます。

| ループ | 既定の実行タイミング | 内容 |
|---|---|---|
| **ランナーへの配布** | 2 秒ごと | 待機中のジョブと中止をランナーに渡します。別のノードで起動されたものは次の回でランナーに届きます |
| **インバウンド接続** | 10 秒ごと | このノードが保持できる [インバウンド](../rte/modes.html#inbound) ランナーに接続します。ソケットを失ったものにも再接続します |
| **終了ジョブの整理** | 60 秒ごと | 別のノードで終了したジョブについて、このノードが保持していたものを手放します |

ループは Web アプリを実行するすべてのノードで動くので、アプリノードが複数あればそれぞれが自分のループを持ちます。cron の最小単位である
1 分はこれらには粗すぎるため、それぞれが指定した秒数ごとに実行されます。

## システムの一覧

[ジョブ](./) ページは、管理者（ロールオプション `showSettings` ）向けに、 **未来** の下の **システム** に処理の数とともに処理を一覧表示します。

一覧には処理とループごとに 1 行があり、1 分ごとに読み直されます。

| 列 | 表示内容 |
|---|---|
| **名前** | 処理の名前 |
| **スケジュール** | 実行タイミングを言葉で（ *毎時* 、 *2 秒ごと* ）、ホバーで cron を表示。実行されない処理は **オフ** |
| **最終実行** | 前回の実行が始まった時刻。一度も実行されていなければダッシュ |
| **次回実行** | 次に実行される時刻 |
| **ステータス** | 前回の実行の結果： `success` または `failed` |

**列** では、各処理の内容である **説明** も選べます。行をクリックすると処理のページが開きます。処理はアプリ自身のものなので、
追加も削除もできません。

## 処理のページ

処理のページには三つのタブがあり、その上に **今すぐ実行** と **保存** 、すべてのタブを一度に絞り込む検索ボックスがあります。

| タブ | 表示内容 |
|---|---|
| **詳細** | **名前** と **説明** 、 **前回の起動** （失敗したときはホバーでエラー）、前回の実行の **結果** 、 **最終実行** 、 **次回実行** 、ループでは応答した **ノード** 、そして **適用される設定** |
| **スケジュール** | 実行タイミング：処理では cron、ループでは秒単位の **間隔** |
| **実行履歴** | 記録されたすべての実行。新しいものから順に表示 |

**適用される設定** には `JOB_RETENTION_DAYS` 90 のように変数とその値が表示され、 **設定で変更** でそれを変更する設定タブが開きます。
そのような設定のない処理はダッシュを表示します。

### スケジュールタブ
{: .no_toc }

処理の cron は、スケジュールと同じエディターで編集します。プリセット、言葉による式の説明、次の 3 回の実行が、サーバーの
タイムゾーンで表示されます。5 つのフィールド（分、時、日、月、曜日）を取り、再び実行されるものでなければなりません。ループは
範囲内の整数の秒数を取り、その範囲はフィールドの下の行に表示されます。

**保存** は、設定ページと同じように値を管理された設定ファイルに書き込み、再起動なしで直ちにすべてのノードに適用します。プロセスの
環境で設定された値、または [`ALLOW_ENV_EDIT`](../customization/configuration.html#env_ALLOW_ENV_EDIT)`=0` のときのすべての値は、
読み取り専用で表示され、 *環境変数で設定されています* という行とその名前が示されます。

### 実行履歴タブ
{: .no_toc }

処理の実行は 1 回ごとに 1 行で、次の列があります。

| 列 | 表示内容 |
|---|---|
| **実行者** | **今すぐ実行** を選んだユーザー（ `admin (local)` のように）、または cron による実行では **スケジュール** |
| **開始時刻** 、 **終了時刻** 、 **所要時間** | 実行の開始と終了の時刻と、かかった時間 |
| **ステータス** | `success` または `failed` |
| **結果** | 実行した内容（ *Removed 120 jobs* など）、またはそのエラー |
| **ノード** | 実行したノード |

過去 30 日の実行が、処理ごとに最大 1000 件まで保持されます。1 分ごとに実行される処理では、おおよそ直近 16 時間分です。

ループは実行回数が多すぎるため、1 回ごとに 1 行にはなりません。代わりに、その **実行履歴** タブにはノードごとに次のものが表示されます。

* 1 時間ごとの集計（ *1,800 passes, 0 failed* など）。その 1 時間の回のどれかが失敗すれば `failed` になります。
* **今すぐ実行** ごとの 1 行。 *Run now: done* またはエラーが表示されます。
* タイマーによる回が失敗したときの `failed` の行。同じエラーについては最大で 1 分に 1 回です。

### 今すぐ実行
{: .no_toc }

**今すぐ実行** は、処理を実行するノードで処理を直ちに実行し、その実行をあなたの名前で記録します。処理の実行中と、 **オフ** の
処理では無効です。夜間バックアップのような長い実行は、ページが応答した後も続きます。

ループの **今すぐ実行** は、ページを提供しているノードで 1 回実行し、ランナーハブが動いていないノードでは拒否されます。どの
**今すぐ実行** も、監査ログに `system.task.run` として記録されます。

## 処理の実行タイミングを変える

各処理と各ループには、そのタイミングを決める環境変数があり、 **スケジュール** タブがそれを書き込みます。どれも再起動なしで反映されます。

| 変数 | 既定値 | 処理 |
|---|---|---|
| [`ABANDONED_JOBS_CRON`](../customization/system-tasks.html#env_ABANDONED_JOBS_CRON) | `0 * * * *` | 放棄されたジョブ |
| [`DEAD_NODES_CRON`](../customization/system-tasks.html#env_DEAD_NODES_CRON) | `* * * * *` | 停止したノード |
| [`SCHEDULE_ENDS_CRON`](../customization/system-tasks.html#env_SCHEDULE_ENDS_CRON) | `* * * * *` | スケジュールの終了 |
| [`SCHEDULE_RESYNC_CRON`](../customization/system-tasks.html#env_SCHEDULE_RESYNC_CRON) | `*/5 * * * *` | スケジュール再同期 |
| [`TOKEN_CLEANUP_CRON`](../customization/system-tasks.html#env_TOKEN_CLEANUP_CRON) | `0 3 * * *` | 期限切れトークン |
| [`AUDIT_CLEANUP_CRON`](../customization/system-tasks.html#env_AUDIT_CLEANUP_CRON) | `30 3 * * *` | 監査ログの整理 |
| [`JOB_CLEANUP_CRON`](../customization/system-tasks.html#env_JOB_CLEANUP_CRON) | `30 2 * * *` | ジョブの整理 |
| [`NIGHTLY_BACKUP_CRON`](../customization/system-tasks.html#env_NIGHTLY_BACKUP_CRON) | `0 0 * * *` | 夜間バックアップ |
| [`STORED_JOB_CLEANUP_CRON`](../customization/system-tasks.html#env_STORED_JOB_CLEANUP_CRON) | `0 4 * * *` | 保存済みジョブの整理 |
| [`CONFIG_SEED_RELOAD_CRON`](../customization/configuration.html#env_CONFIG_SEED_RELOAD_CRON) | `* * * * *` | 構成シードの再読み込み |
| [`RUNNER_DISPATCH_SECONDS`](../customization/system-tasks.html#env_RUNNER_DISPATCH_SECONDS) | `2` （1 から 60） | ランナーへの配布 |
| [`RUNNER_DIAL_SECONDS`](../customization/system-tasks.html#env_RUNNER_DIAL_SECONDS) | `10` （2 から 300） | インバウンド接続 |
| [`RUNNER_PRUNE_SECONDS`](../customization/system-tasks.html#env_RUNNER_PRUNE_SECONDS) | `60` （10 から 3600） | 終了ジョブの整理 |

環境に手で設定された、有効な cron でない値や範囲外の秒数は無視され、既定値が使われます。

### CONFIG_SEED_RELOAD_SECONDS
{: .no_toc }

7.8.0 より前は、構成シードは [`CONFIG_SEED_RELOAD_SECONDS`](../customization/configuration.html#env_CONFIG_SEED_RELOAD_SECONDS) ごとに確認されていました。
この変数は 7.8.0 から非推奨となり、 `CONFIG_SEED_RELOAD_CRON` に置き換えられ、8.0 で削除されます。 `CONFIG_SEED_RELOAD_CRON`
が設定されていないあいだは、起動時にログへ警告を出したうえで、引き続き cron として読まれます。

| `CONFIG_SEED_RELOAD_SECONDS` | 読み替え |
|---|---|
| `60` | `* * * * *` 、1 分ごと |
| `3600` までの 60 の倍数 | 指定した分ごと。 `300` なら `*/5 * * * *` （ `3600` は `0 * * * *` ） |
| 60 を割り切る 60 未満の数 | 指定した秒ごと |
| `0` | 再読み込みはオフ |
| その他の数 | これらのうち最も近いもの。ログにそれが示されます |

処理の **スケジュール** タブは、その cron を *非推奨の CONFIG_SEED_RELOAD_SECONDS によるもの。保存した cron で置き換わります。*
という行とともに表示します。 **保存** は `CONFIG_SEED_RELOAD_CRON` を書き込み、以後はそれが古い変数より優先されます。
