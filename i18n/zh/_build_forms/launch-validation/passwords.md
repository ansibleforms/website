# 密码
{: .no_toc }

密码字段如何验证、存储以及如何不出现在 API 中
{: .fs-6 .fw-300 }

1. TOC
{:toc}

---

密码字段的验证方式与其他字段相同。但它的值保存在服务器上，从不交还给
客户端。

---

## 密码保存在哪里

服务器把密码与作业一起保存在其 extravars 中：

* 这样**审批**就可以用用户输入的密码继续执行作业。
* 当运行验证不是 `enforce` 时，**按原样重新运行**可以重放该密码。

保存的密码只在服务器上使用。

---

## API 返回什么

任何 API 都不会返回密码：

* 通过 REST API 或 MCP 服务器的 `get_job` 读取作业时，其表单中的每个 `password` 字段都会被掩码，包括
  列表行和 YAML 子表单中的字段。
* `MASK_EXTRAVARS_REGEX` （默认 `password|secret|token` ）还会掩码名称匹配的每个 extravar，用于
  那些不是密码字段的机密。

---

## 重新运行时收到什么

为了预填重新运行的表单，浏览器会收到作业的原始表单数据。这些数据从不包含密码，即使在
列表行或 YAML 子表单中也没有，因此用户需要重新输入密码。

被表单依赖关系隐藏的密码字段不需要填写，也就不必重新输入。
