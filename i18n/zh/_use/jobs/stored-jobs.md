## 保存的作业

保存的作业会保留表单的值，以便您再次加载它们，而不必每次都填写相同的字段。

要保存，请填写表单，打开**提交**旁边的下拉菜单并选择**保存**。在**保存表单数据**中，输入**名称**、可选的**描述**，并在**删除**中选择何时删除（参见[何时删除](#when-it-is-removed)），然后保存。密码字段和常量字段从不保存。子表单的**保存**按钮旁边也有同样的**保存**操作，可以保留尚未完成的值而不对其进行验证。

要加载，请在表单顶部选择**从已保存项加载**。**加载已保存的表单**会列出您为该表单保存的作业，以及
其创建日期和过期日期；选择其中一个即可用其值填充表单。在您提交之前不会运行任何内容。

保存的作业保存在 AnsibleForms 数据库中（表 `stored_jobs` ），包含表单名称、以
`<type>/<username>` 表示的您的用户（例如 `local/admin` ），以及 JSON 格式的值。名称在每个用户和表单中必须唯一；
用相同的名称再保存一个会失败，并提示 "A saved form with this name already exists"。

## 管理保存的作业

**保存的作业**页面列出保存的作业，以及其表单、用户、创建日期和过期日期，需要 `allowStoredJobs` 。

从 7.6.0 起，仅凭 `allowStoredJobs` 即可打开**作业 > 已保存**和**添加保存的作业**，之前还需要 `showSettings` 或
`allowScheduledJobs`。其**表单**列表提供您的角色可以打开的表单；拥有 `showSettings` 或 `allowScheduledJobs` 的用户可以看到所有表单。

从 7.7.0 起，列表有一个可排序的**最后使用**列，可以把仍在使用的保存的作业与已被弃用的区分开。

- **编辑**会打开该保存作业自己的页面：其**详细信息**（名称、描述、表单、用户、创建时间和最后使用时间，以及何时删除）、其**值**（即以 YAML 表示的已保存
  字段值，可以在那里修改并保存）以及其**运行记录**。
- **在表单中打开**会打开其表单并填入保存的值；在您提交之前不会运行任何内容。
- **删除**会将其移除。您可以删除自己保存的作业；拥有 `showSettings` 的用户可以删除任何保存的作业。

## 最后使用与运行记录

从 7.7.0 起，保存的作业会记录其最后使用时间以及从它启动的作业，让您知道哪些仍在使用。

以下启动算作对保存的作业的一次使用：

| 启动 | 何时计数 |
|---|---|
| 从它打开的表单（**在表单中打开**），或用**从已保存项加载**填充的表单 | 作业启动时 |
| 从该表单**稍后运行** | 计划的运行触发时，而不是计划时 |
| 对从它启动的作业**重新运行** | 重新运行开始时，无论值是否更改 |
| 带有它的 MCP `launch_job` 或 `plan_job` | 同上 |

计划的运行从不计数，即使该计划是从保存的作业创建的：计划会保留自己的一份值。只有当用户可以看到该保存的作业时，启动才会计数；此后被删除或隐藏的会被跳过，作业仍会运行。

作业页面会显示作业是从哪个保存的作业启动的，在您可以看到它时附带链接。保存的作业页面的**运行记录**选项卡列出从它启动的、您可以看到的作业，以及其状态、开始时间、结束时间和持续时间。

## 何时删除

每个保存的作业都会说明何时删除：从不、在指定日期，或在未使用一定天数后。

| 选项 | 作用 |
|---|---|
| **从不** | 保留它，直到有人删除它。设置了 `STORED_JOB_UNUSED_DAYS` 时不提供此选项 |
| **在指定日期** | 在该日期删除它 |
| **未使用超过** N 天 | 在这么多天内没有从它启动任何作业时删除它 |

管理员可以设置 [`STORED_JOB_UNUSED_DAYS`](../customization/retention.html#env_STORED_JOB_UNUSED_DAYS)（设置 > 常规 > 保留期限）。设置后，它会删除未使用达到该天数的所有保存的作业，保存的作业自己的天数只能更少，保存对话框从该天数开始，在指定日期删除的作业在未使用达到该时长时也会被删除。天数从最后一次使用开始计算，从未使用过的保存的作业则从保存时开始计算。其默认值 0 从不因未使用而删除作业。

保存的作业每天 04:00（按 `LOG_TZ` ）删除，以其日期和天数中先到者为准。
