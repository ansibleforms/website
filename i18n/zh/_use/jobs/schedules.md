## 表单操作

表单不只能立即运行：其**提交**按钮旁边的下拉菜单中还有另外三个操作。

| 操作 | 作用 | 角色选项 |
|---|---|---|
| **调度（周期性）** | 创建一个按 cron 表达式运行表单的调度 | `allowScheduledJobs` |
| **稍后运行（一次性）** | 创建一个在您选定的日期和时间运行一次表单的调度 | `allowPlannedJobs` |
| **保存** | 保存字段值，以便以后再次加载到表单中 | `allowStoredJobs` |

角色选项关闭的操作不会显示。执行任何这些操作之前，表单都会像**提交**时一样进行验证。两种
调度操作都会在**作业 > 已计划**下创建一个条目；**保存**会在**保存的作业**页面上创建一个条目。
[作业](./)页面的侧栏在**未来**下以**已计划**和**已保存**打开它们。这些角色选项的说明
见[角色选项](../config/roles.html#role-options)。

{: .warning }
> 请把 `allowScheduledJobs` 视为管理员级别的选项。其调度不归创建它们的用户所有：每个拥有
> 该选项的用户都能看到并修改所有调度。这样的调度还会以管理员权限运行任何表单，无论
> 创建者自己的访问权限如何。只把它授予您会像信任管理员一样信任的角色。

{: .note }
> **稍后运行（一次性）** 只需要 `allowPlannedJobs` 。对于没有 `allowScheduledJobs` 的用户，它会**以该
> 用户身份**计划一次运行：服务器检查该用户是否可以运行该表单，到时间时作业以该用户身份运行，并归其所有
> （参见[计划的运行](#planned-runs)）。

## 调度表单

填写表单，然后打开**提交**旁边的下拉菜单，选择其中一个调度操作。

- **调度（周期性）** 会打开**创建调度**：输入**名称**和 **Cron 表达式**（默认值 `0 0 * * *`
  表示每天午夜运行），然后选择**创建调度**。
- **稍后运行（一次性）** 会打开**稍后运行**：输入**名称**并选择**运行时间**的日期和时间，然后选择
  **调度作业**。

名称在所有调度中必须唯一。调度会保存表单的名称，以及表单在那一刻生成的 extravars 的副本，
以 YAML 格式写入；每次运行都使用该副本，因此要更改作业收到的内容，请在调度自己的页面上编辑它。
如果要改用 rrule 安排时间，或为其设置结束，请打开它的页面并修改其**计划**选项卡。

## 调度列表

**作业 > 已计划**列出所有调度，需要 `allowScheduledJobs` ；点击一行会打开该调度自己的页面。

| 列 | 显示 |
|---|---|
| **已启用** | 调度是否按其自身的时间安排运行 |
| **名称**和**表单** | 调度，以及它运行的表单 |
| **调度** | 用通俗语言描述的时间安排，例如 *At 02:00 AM*；将鼠标悬停其上可查看 cron 或规则本身 |
| **上次运行** | 上一次运行的时间 |
| **下次运行** | 下一次运行的时间，没有后续运行时显示短横线 |
| **状态** | 上一次启动：是否启动了作业，或在启动过程中显示**正在启动…** |

**调度**列将一次性调度显示为**一次性运行**。无法用通俗语言描述的 rrule 会按原样
显示。每一行的菜单提供：

| 操作 | 作用 |
|---|---|
| **编辑** | 打开该调度的页面 |
| **立即运行** | 立即运行该调度，不等待其时间安排 |
| **启用**或**禁用** | 根据**已启用**列的状态，打开或关闭该调度 |
| **删除** | 移除该调度；它会立即停止运行 |

**新建调度**分三步从头创建一个调度：**详情**（其**名称**、**描述**和**表单**）、
**计划**（其时间安排和结束）以及 **Extra vars**。**Extra vars** 是 YAML，没有表单来填写它，因此请自行添加
playbook 需要的值，以字典（键: 值对）的形式。

## 调度的页面

调度的页面以选项卡的形式呈现其对话框的各个步骤，右上角有**立即运行**、**删除**和**保存**。

| 选项卡 | 内容 |
|---|---|
| **详情** | 其来源、**名称**、**描述**、**表单**，然后是**上次启动**、**已启动的作业**、**上次运行**、**下次运行**和**已启用** |
| **计划** | 它的时间安排（参见[调度的时间安排](#timing-a-schedule)）以及它如何结束（参见[调度的结束](#the-end-of-a-schedule)） |
| **Extra vars** | 作业收到的 YAML；对于保存在 git 中的调度，还有其文件中的提示项 |
| **运行记录** | 它启动的作业，最新的在前；点击一行会打开该作业 |

**上次启动**以状态的形式说明上一次启动的情况：失败时，将鼠标悬停其上会显示原因。**已启动的作业**链接到
它启动的作业，您可以打开它查看其最终结果。**运行记录**选项卡列出您有权查看的作业，以及其运行身份、
开始时间、结束时间、持续时间和状态；数量显示在选项卡标题中。

**已启用**开关可以暂停调度而无需删除它，与页面上的每个字段一样通过**保存**保存。关闭的调度
仍保留在列表中，其设置不变，但不会自行运行：周期性调度会跳过其运行，一次性调度则会越过其
时间一直等待，直到再次打开。**立即运行**仍然可以按需运行它。新的调度默认开启。

## 调度的时间安排

调度的时间安排有三种方式，在其**计划**选项卡的**时间安排**下选择；rrule 是 7.8.0 新增的。

| 时间安排 | 运行 | 参见 |
|---|---|---|
| **Cron** | 周期性，按服务器时区的 cron 表达式 | [Cron 表达式和时区](#cron-expressions-and-time-zone) |
| **重复规则 (rrule)** | 周期性，按使用自身时区的 iCal 规则 | [重复规则](#recurrence-rules) |
| **一次性运行** | 一次，在指定的日期和时间 | [调度如何运行](#how-a-schedule-runs) |

使用 cron 或 rrule 时，编辑器会显示接下来的三次运行，并在调度的结束处截止。更改时间安排
只会保留所选的那一种：从 cron 切换到 rrule 的调度会失去其 cron。

---

## Cron 表达式和时区

周期性调度可以使用标准的 5 字段 cron 表达式：分钟、小时、月中的日、月份和星期。

| 表达式 | 运行时间 |
|---|---|
| `*/15 * * * *` | 每 15 分钟 |
| `0 2 * * *` | 每天 02:00 |
| `30 7 * * 1-5` | 周一至周五 07:30 |
| `0 0 1 * *` | 每月第一天的午夜 |

cron 编辑器会用文字描述表达式，提供预设，并预览接下来的几次运行。服务器会拒绝它无法运行的表达式，
或者永远不会发生的表达式。更多示例，以及编辑器不接受的 cron 功能，请参阅常见问题中的
[我可以使用哪些 cron 表达式？](../faq.html#which-cron-expressions-can-i-use)。

{: .note }
> Cron 调度按服务器的时区运行，该时区由 [`LOG_TZ`](../customization/logging.html#env_LOG_TZ) 设置（默认 `UTC` ），
> 而不是您的个人资料或浏览器的时区。cron 编辑器也按同一时区预览接下来的运行。

## 重复规则

从 7.8.0 起，周期性调度也可以改用 iCal 重复规则（rrule），它按自己的时区运行。

```text
DTSTART;TZID=Europe/Brussels:20261020T020000 RRULE:FREQ=DAILY;INTERVAL=1
DTSTART:20261019T060000Z RRULE:FREQ=WEEKLY;INTERVAL=1;BYDAY=MO
DTSTART;TZID=America/New_York:20261101T073000 RRULE:FREQ=MONTHLY;INTERVAL=1;BYDAY=MO,TU,WE,TH,FR;BYSETPOS=-1
```

第一条在布鲁塞尔时间每天 02:00 运行，第二条在 UTC 时间每周一 06:00 运行，第三条在纽约时间每月最后一个
工作日的 07:30 运行。一条规则占一行，各部分以空格分隔：

| 部分 | 含义 |
|---|---|
| `DTSTART` | 第一次运行，带 `TZID`（IANA 时区，例如 `Europe/Brussels`，或偏移量，例如 `UTC+5` 或 `GMT-3`），或以 `Z` 结尾的 UTC 时间 |
| `RRULE` | 何时重复：`FREQ` 加上至少为 1 的 `INTERVAL`，并按需使用 `BYDAY`、`BYHOUR`、`BYMONTHDAY`、`COUNT`、`UNTIL` …；一条或多条 |
| `EXRULE` | 可选：要跳过的运行的规则 |

服务器会拒绝它无法运行的规则，并说明原因：

- 没有 `DTSTART`、有多个，或有一个不带时区，以及 `EXDATE` 或 `RDATE`；
- 没有 `INTERVAL` 的规则、`FREQ=SECONDLY`、带数字的 `BYDAY`（`5MO`），或 `COUNT` 与 `UNTIL` 同时使用；
- 大于 999 的 `COUNT`、超出范围的 `BYxxx` 数值（`BYHOUR` 为 0 到 23，`BYSETPOS` 为 1 到 366 或 -366 到 -1 …）、不是
  星期几的 `WKST`、不是真实日期的 `DTSTART` 或 `UNTIL`（`20300230`），或在一条规则中出现两次的部分；
- 永远不会触发的规则：在其 `DTSTART` 之后 50 年内没有任何运行，例如从午夜开始的 `FREQ=HOURLY;INTERVAL=2;BYHOUR=1`，
  它只会遇到偶数小时。

编辑器是一个文本框：新的 rrule 默认为按浏览器时区每天午夜运行。它会立即说明规则为何会被拒绝，
否则按规则自身的时区显示接下来的三次运行；如果其 `UNTIL` 或 `COUNT` 已过，则显示**此 rrule 之后没有运行。**
夏令时切换跳过的时间，会在时钟到达时运行（在时钟从 02:00 跳到 03:00 的那一夜，02:30 会在 03:30 运行），
与 cron 相同；时钟显示两次的时间只运行一次，即第一次。

## 调度的结束

从 7.8.0 起，按 cron 或 rrule 安排时间的调度可以结束；在其**计划**选项卡的**结束**下选择一个选项。

| 结束 | 调度结束于 |
|---|---|
| **从不** | 永不结束：这是默认值，7.8.0 之前的所有调度也是如此 |
| **在某日期** | 所选的日期和时间：之后不再运行 |
| **运行** … **次后** | 它总共启动了这么多作业时，即其**运行记录**选项卡列出的作业；该字段会显示目前已启动的数量 |

**结束时**，它会被关闭（**禁用**，默认）或删除（**删除**）。**计划结束**系统任务每分钟
应用一次结束条件，达到运行次数的调度会在最后一次运行之后立即结束。rrule 自身的
`UNTIL` 或 `COUNT` 仍然有效；结束条件是在此之上额外生效的。

一次性调度没有结束：它随其运行而结束。其**运行后删除**开关默认开启，会在运行后删除它；
关闭时，调度在运行后被禁用，并与其结果一起保留。

## 调度如何运行

调度到期时会进入队列，服务器每 10 秒检查一次队列，并逐个启动排队的调度。

- **周期性**调度在上一次运行仍在排队或运行时会跳过当次运行，因此各次运行永远不会重叠。
- **一次性**调度在其时间之后一分钟内运行，然后被删除（如果**运行后删除**已关闭，则被关闭
  并保留），通过**立即运行**启动时也是如此。
- **状态**在作业已启动时为 `success` ，无法启动时为 `failed` 。 `success` 只表示作业已
  运行：请打开作业查看其最终结果。

用 `allowScheduledJobs` 创建的调度以内置用户 `Schedule Service` （类型 `schedule` ）运行，拥有
`admin` 角色。它可以运行任何表单，无论创建调度的人有何访问权限，其 extravars 中的 `ansibleforms_user`
描述的就是该用户。而[计划的运行](#planned-runs)则以计划它的用户身份运行。

作业还会得到一个 `schedule` 对象，这样 playbook 就知道是调度启动了它：

```yaml
schedule:
  id: 3
  name: Nightly cleanup
  description: ''
  form: Cleanup servers
  one_time_run: null
```

其 `one_time_run` 是一次性调度运行的时间，周期性调度则为 `null`。它还包含调度的其他
设置，例如 `enabled` 和 `repository`，以及 `run_at`：即 7.8.0 之前名称下的同一时间（已弃用，将在 8 中移除）。

## 计划的运行

没有 `allowScheduledJobs` 的用户使用**稍后运行（一次性）** 时，会创建一个计划的运行：一个与该用户绑定的一次性调度。

- **计划时**，服务器会检查该用户是否可以运行该表单（其 `roles` ），详细模式需要
  `allowVerboseMode` 。计划的运行始终是一次性的；cron 表达式或 rrule 会被拒绝。
- **在运行验证为 `enforce` 时**，字段值会在计划时检查，因此本会被拒绝的运行会在
  用户还在查看时就被拒绝。
- **运行时**，作业以该用户身份运行并归其所有，经过与从浏览器运行相同的检查：
  当时的表单角色、去除保留的 extravars，以及运行验证。 `ansibleforms_user` 描述的就是该用户。

计划者看不到**作业 > 已计划**，因为它需要 `allowScheduledJobs` ；作业会出现在他们自己的作业历史中。
计划的运行在运行后总是会被删除。

## 表单发生变化时

调度按名称引用其表单，并在每次运行时按表单当时的定义运行。

- **表单被编辑**：下一次运行使用新的定义（playbook、模板、清单）以及调度中保存的
  extravars。表单不会被渲染，因此不会重新计算任何字段；请编辑调度的 extra vars 使其匹配。
- **表单被重命名或移除**：运行失败，**状态**变为 `failed` ，将鼠标悬停在**上次启动**上会显示
  `Failed to launch : No such form '<name>'` 。请编辑调度并选择正确的表单，或者删除它。

## 作业历史中的调度作业

调度的每次运行都会创建一个普通作业，列在[作业](./)页面上，其用户为 `Schedule Service` ；
如果是计划的运行，则为计划它的用户。

`Schedule Service` 作业不属于创建调度的人，因此只有管理员和
拥有 `showAllJobLogs` 的用户才能看到；计划的运行所产生的作业，其用户也能看到。调度的**运行记录**选项卡
列出它启动的作业，其**已启动的作业**链接到最后一个。

## git 仓库中的调度

从 7.8.0 起，调度也可以保存在 git 仓库中，作为其 YAML 文件中 `controller_schedules:` 列表的条目。

最多只有一个仓库具有**调度**用途：每次拉取时，其条目都会读入**作业 > 已计划**，按 `cron`、`rrule` 或
`one_time_run` 安排时间；在应用中创建或修改的调度会写回其文件，等待仓库的推送。这样的调度会在其页面上
显示其文件，其结束只会将其关闭。参见 [Git 仓库](../repositories/)。

## 在 API 中

从 7.8.0 起，API 中的调度有三个时间安排字段，其中恰好设置一个：`cron`、`rrule` 或 `one_time_run`。

| 字段 | 内容 |
|---|---|
| `cron` | 一个 cron 表达式 |
| `rrule` | 一条重复规则，占一行 |
| `one_time_run` | 其唯一一次运行的时间，带偏移量或 `Z` 的 ISO 8601 时间（`2026-11-15T22:00:00+01:00`） |
| `ends`、`end_at`、`end_count`、`end_action` | 其结束：`never`、`date` 或 `count`，其日期，其运行次数，以及 `disable` 或 `remove` |
| `remove_after_run` | 一次性调度：`false` 表示运行后将其关闭并保留 |

{: .warning }
> 7.8.0 之前 API 接受的组合，即 `one_time_run: true` 加 `run_at`，自 7.8.0 起已弃用，并将在 8 中移除。它仍会被读取为
> 该时间的 `one_time_run`，同时在服务器日志中记录一条警告；`one_time_run: false` 加 cron 会被读取为该 cron。
