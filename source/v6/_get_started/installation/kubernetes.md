# Kubernetes
{: .no_toc }

Install AnsibleForms and its MySQL database with the Helm chart
{: .fs-6 .fw-300 }

1. TOC
{:toc}

---

The Helm chart deploys AnsibleForms with MySQL (see the [values reference](https://github.com/ansibleforms/helm-charts/blob/release/6.x/charts/ansibleforms/VALUES.md)).

{: .note }
> **Stay on the 6.x charts** `--version "~6"` keeps you on the 6.x charts, which run AnsibleForms 6; without it you get the
> newest chart, for AnsibleForms 7. Every command on this page passes it.

---

## Prerequisites

Before you start, you need:

* **Kubernetes cluster** : with `kubectl` configured to reach it
* **Helm 3** : to install and upgrade the chart
* **Storage** : a StorageClass for dynamic provisioning, or pre-created PersistentVolumes
* **Ingress controller** : only if you want to expose AnsibleForms through an ingress

---

## 2. Configure the storage

Both AnsibleForms and MySQL store their data on a persistent volume. Set the StorageClass and size of each:

```yaml
storages:
  server:
    className: longhorn
    size: 5Gi
    accessMode: ReadWriteOnce
  mysql:
    className: longhorn
    size: 5Gi
    accessMode: ReadWriteOnce
```

An empty `className` uses the cluster's default StorageClass. The access mode defaults to `ReadWriteMany`, which many storage
classes do not offer; `ReadWriteOnce` is fine with a single replica. For pre-created PersistentVolumes, see the chart's
[README](https://github.com/ansibleforms/helm-charts/tree/release/6.x/charts/ansibleforms).

---

## 3. Set the credentials

AnsibleForms needs an admin account, a database password and an `ENCRYPTION_SECRET`, the key that encrypts the credentials
stored in AnsibleForms. Never change that key once data exists. Supply them in one of three ways:

<div class="af-tabs" data-tab-group="helmcreds">
<div class="af-tab-list" role="tablist">
<button type="button" role="tab" class="af-tab" data-tab="values" aria-selected="true">In the values file</button>
<button type="button" role="tab" class="af-tab" data-tab="generate" aria-selected="false">Generated by the chart</button>
<button type="button" role="tab" class="af-tab" data-tab="existing" aria-selected="false">Existing Secret</button>
</div>
<div class="af-tab-panel" role="tabpanel" data-tab="values" markdown="1">

Set them in `my_values.yaml`. The chart stores them in a Secret named `<release>-secrets`:

```yaml
applications:
  server:
    env:
      ADMIN_USERNAME: admin
      ADMIN_PASSWORD: a-strong-password
      ENCRYPTION_SECRET: a-random-string-of-32-characters
  mysql:
    password: a-strong-database-password
```

</div>
<div class="af-tab-panel" role="tabpanel" data-tab="generate" markdown="1" hidden>

Let the chart generate whatever you do not supply, on the first install. It keeps the same values on every
upgrade afterwards:

```bash
--set secrets.generate=true
```

This does not work with Argo CD or Flux, which render the chart without access to the cluster. The generated Secret
survives `helm uninstall`; back it up, because `ENCRYPTION_SECRET` cannot be recovered.

</div>
<div class="af-tab-panel" role="tabpanel" data-tab="existing" markdown="1" hidden>

Point the chart at a Secret you manage, for example with External Secrets, Sealed Secrets or SOPS. The chart
then creates none:

```yaml
secrets:
  existingSecret: ansibleforms-credentials
```

The Secret must hold `DB_USER`, `DB_PASSWORD`, `ENCRYPTION_SECRET`, `ADMIN_USERNAME` and `ADMIN_PASSWORD`.

</div>
</div>

## 4. Install the chart

Install the chart into its own namespace with your values:

```bash
helm upgrade --install ansibleforms ansibleforms/ansibleforms --version "~6" \
  --namespace ansibleforms --create-namespace \
  --values my_values.yaml
```

With the OCI registry, use `oci://ghcr.io/ansibleforms/charts/ansibleforms` as the chart. In anything that runs unattended,
pin an exact 6.x chart version with `--version` (for example `6.3.9`), so that a new release is never installed on its own.

---

## 5. Check the install

The chart includes a test that checks both the web server and the database connection:

```bash
helm test ansibleforms --namespace ansibleforms --logs
```

The test ends with `OK` when AnsibleForms answers and its database accepts connections.

## 6. Open AnsibleForms

How you reach AnsibleForms depends on how the server is exposed:

<div class="af-tabs" data-tab-group="helmaccess">
<div class="af-tab-list" role="tablist">
<button type="button" role="tab" class="af-tab" data-tab="portforward" aria-selected="true">Port forward</button>
<button type="button" role="tab" class="af-tab" data-tab="loadbalancer" aria-selected="false">LoadBalancer</button>
<button type="button" role="tab" class="af-tab" data-tab="ingress" aria-selected="false">Ingress</button>
</div>
<div class="af-tab-panel" role="tabpanel" data-tab="portforward" markdown="1">

With the default `ClusterIP` service and no ingress, nothing is exposed outside the cluster. Forward a local port to
have a look:

```bash
kubectl -n ansibleforms port-forward svc/ansibleforms-server 8080:80
```

Then open `http://127.0.0.1:8080/`.

</div>
<div class="af-tab-panel" role="tabpanel" data-tab="loadbalancer" markdown="1" hidden>

Set `services.server.type: LoadBalancer` (optionally with a fixed address in `services.server.loadbalancer.ip`),
then wait for the service to get its address:

```bash
kubectl -n ansibleforms get svc ansibleforms-server -w
```

</div>
<div class="af-tab-panel" role="tabpanel" data-tab="ingress" markdown="1" hidden>

Enable the ingress and set the host name that routes to your ingress controller:

```yaml
ingress:
  enabled: true
  className: nginx
  hostname: ansibleforms.example.com
  tls:
    enabled: true
```

The chart's [README](https://github.com/ansibleforms/helm-charts/tree/release/6.x/charts/ansibleforms) covers TLS behind an ingress, including the backend setting that HTTPS on the
server needs.

</div>
</div>

## 7. Sign in

Sign in as the admin user, `admin` by default. To read the password from the Secret:

```bash
kubectl -n ansibleforms get secret ansibleforms-secrets \
  -o jsonpath='{.data.ADMIN_PASSWORD}' | base64 -d
```

With `secrets.existingSecret`, read it from your own Secret instead.
